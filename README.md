# Планировщик задач

Учебный дипломный проект курса Go-разработчика: веб-сервер с REST API, SQLite и готовым фронтендом.
Позволяет создавать, искать, редактировать, удалять и отмечать задачи выполненными.
 Повторяющиеся задачи при выполнении переносятся на следующую дату, одноразовые удаляются.

## Выполненные дополнительные задания

Выполнил все дополнительные задания:
- Настройка порта через `TODO_PORT` и пути к БД через `TODO_DBFILE`.
- Правила повторения по дням, годам, дням недели и дням месяца (`d`, `y`, `w`, `m`).
- Поиск по заголовку, комментарию и дате.
- Вход по паролю с JWT, действующим 8 часов.
- Dockerfile для сборки и запуска с БД на хосте. Команды проверки приведены ниже.

## Локальный запуск

Нужен Go версии не ниже указанной в `go.mod` (1.24.13). Команды выполняются
из корня проекта: сервер использует каталог `./web`.

```bash
go mod download
go run .
```

Откройте <http://localhost:7540/>. При первом запуске создаётся `scheduler.db`.

Переменные окружения:

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `TODO_PORT` | `7540` | Порт HTTP-сервера |
| `TODO_DBFILE` | `scheduler.db` | Путь к SQLite; родительский каталог должен существовать |
| `TODO_PASSWORD` | пусто | Пароль; пустое значение отключает аутентификацию |
| `TODO_JWT_SECRET` | пусто | Секрет подписи JWT, не менее 32 байт при включённом пароле |
| `TZ` | часовой пояс ОС; в образе `UTC` | Часовой пояс для текущей даты |

Пример локального запуска с другой БД и паролем:

```bash
mkdir -p data
export TODO_DBFILE="$PWD/data/scheduler.db"
export TODO_PASSWORD='замените-на-свой-пароль'
export TODO_JWT_SECRET="$(openssl rand -hex 32)"
export TZ=Europe/Moscow
go run .
```

При включённом пароле откройте <http://localhost:7540/login.html>.
Фронтенд сохраняет токен в куке `token`. Смена пароля или секрета делает ранее выданные токены недействительными.
Сохраняйте секрет между запусками, если хотите продолжать пользоваться действующим токеном.

Приложение само не загружает `.env`: локально задавайте переменные в оболочке.

## Тестирование

**`TestTasks` удаляет все задачи из выбранной БД. Используйте отдельную БД.**
Сервер должен работать во время запуска тестов. В первом терминале:

```bash
mkdir -p test-data
TODO_PASSWORD= TODO_DBFILE="$PWD/test-data/scheduler.db" go run .
```

Во втором терминале, из того же корня проекта:

```bash
TODO_DBFILE="$PWD/test-data/scheduler.db" go test -count=1 ./tests
```

В `tests/settings.go` должны быть `FullNextDate = true`, `Search = true`, `Token = ""`.
По умолчанию `Port = 7540`, `DBFile = "../scheduler.db"`; `TODO_PORT` и `TODO_DBFILE` переопределяют их. Сервер и тесты должны использовать
одинаковые порт и файл БД.

Для тестирования с аутентификацией запустите сервер с паролем и секретом, получите токен и временно запишите его в `Token` в `tests/settings.go`:

```bash
curl -X POST http://localhost:7540/api/signin \
  -H 'Content-Type: application/json' \
  -d '{"password":"замените-на-свой-пароль"}'
```

Запустите тесты с путём к той же тестовой БД. Перед коммитом очистите `Token`.

## Docker

Нужен установленный и запущенный Docker. Следующие команды рассчитаны на Linux/macOS с Bash. Сборка выполняется внутри образа Go, локальный Go не нужен:

```bash
docker build -t go-scheduler .
mkdir -p data
cp .env.example .env
```

В `.env` можно оставить пароль пустым либо заполнить `TODO_PASSWORD` и `TODO_JWT_SECRET` (секрет сгенерируйте через `openssl rand -hex 32`).
Файл `.env` и локальные БД исключены из Git и контекста Docker-сборки.

```bash
docker run -d --name go-scheduler \
  --user "$(id -u):$(id -g)" \
  --env-file .env \
  -e TODO_DBFILE=/data/scheduler.db \
  -p 127.0.0.1:7540:7540 \
  --mount "type=bind,source=$PWD/data,target=/data" \
  go-scheduler
```

Откройте <http://localhost:7540/>. SQLite находится на хосте в `./data/scheduler.db`; если хотите использовать существующую БД, заранее
поместите её в этот каталог при остановленном сервере.

Монтируется весь каталог, чтобы SQLite могла создавать служебные файлы рядом с БД.
`--user` запускает процесс с UID/GID текущего пользователя, чтобы он мог писать в каталог хоста.
Без переопределения образ использует UID/GID `10001:10001`; каталог БД должен быть доступен этому пользователю для записи.

Если меняете `TODO_PORT` в `.env`, измените также порт контейнера справа в `-p`. Например, при `TODO_PORT=8080` используйте `-p 127.0.0.1:7540:8080`.

Логи и остановка:

```bash
docker logs go-scheduler
docker stop go-scheduler
docker rm go-scheduler
```

Для проверки сохранности данных добавьте задачу через браузер, остановите и удалите контейнер, затем повторите команду `docker run` с тем же каталогом `data`. Задача должна сохраниться.
